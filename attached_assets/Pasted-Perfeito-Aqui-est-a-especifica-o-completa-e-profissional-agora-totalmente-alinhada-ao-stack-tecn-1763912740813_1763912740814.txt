🚀 Especificação Final do MVP — NexusLab (Versão Técnica + Funcional)

1. Stack Tecnológico Oficial

Frontend
	•	Next.js (versão 14+) com App Router
	•	TailwindCSS para estilização rápida, responsiva e minimalista
	•	shadcn/ui para componentes modernos, acessíveis e coesos
	•	Lucide-react para ícones clean e padronizados
	•	Framer Motion para animações suaves e microinterações
	•	TanStack Query para gerenciamento de dados em cache
	•	Zod para validação total do schema entre front e back
	•	React Hook Form para formulários padronizados

Backend
	•	API Routes do Next.js ou camada Server Actions
	•	Autenticação via Supabase Auth ou NextAuth.js
	•	Postgres/Supabase como banco principal
	•	Prisma ORM como camada de acesso ao banco
	•	Edge Functions (opcional) para cálculos de IA escaláveis
	•	Integração com OpenAI API (ou modelo open-source)

Infraestrutura
	•	Banco PostgreSQL altamente estruturado
	•	Deploy em Vercel
	•	Storage Supabase para assets (opções)
	•	Logs e auditoria via Supabase Functions

⸻

🧱 2. Banco de Dados — Estrutura Profissional

O banco é um dos pontos mais importantes do MVP, então ele deve ser:
	•	Escalável
	•	Normalizado
	•	Com constraints fortes
	•	Métricas de auditoria obrigatórias
	•	Relacionamentos claros
	•	Índices otimizados

📌 Tabelas principais

users
	•	id (PK)
	•	name
	•	email (unique)
	•	role (user/admin/company)
	•	created_at, updated_at

skills
	•	id (PK)
	•	name
	•	category
	•	description

user_skills
	•	id (PK)
	•	user_id (FK → users)
	•	skill_id (FK → skills)
	•	level (0–100)
	•	updated_at

career_routes
	•	id (PK)
	•	user_id (FK → users)
	•	current_position
	•	target_position
	•	steps (JSON)
	•	created_at

learning_trails
	•	id (PK)
	•	title
	•	description
	•	difficulty
	•	created_at

trail_modules
	•	id (PK)
	•	trail_id (FK)
	•	title
	•	type (video, texto, desafio)
	•	content (JSON)
	•	order

user_trail_progress
	•	id (PK)
	•	user_id
	•	trail_id
	•	progress_percentage

labs
	•	id
	•	name
	•	description
	•	scenario_data (JSON)
	•	created_at

lab_results
	•	id
	•	user_id
	•	lab_id
	•	score
	•	decisions (JSON)

opportunities
	•	id
	•	company_id
	•	title
	•	description
	•	requirements (JSON)
	•	created_at

applications
	•	id
	•	user_id
	•	opportunity_id
	•	status

wellbeing_logs
	•	id
	•	user_id
	•	mood (1–5)
	•	note
	•	created_at

Tudo com:
	•	foreign keys
	•	cascade delete quando apropriado
	•	índices em FK
	•	tabela de auditoria (log de ações)
